# Reviewed detection export

Choose **Chapter 9 · reviewed single-object detection** in the existing release menu after saving and separately reviewing image boxes. Select exact record revisions, preview, resolve any blockers, then freeze and download `image_detection_v1`. Preview never saves an editor draft or approves a target. Changes to settings, selected revisions, source bytes or known connected-family evidence retire the proof. Frozen archives remain immutable after later edits or reload.

This profile is the roadmap's pinned Chapter 9 `train_detector.Images` reader. Canonical detection continues to use its existing COCO projection, including multiple labels/boxes and finite fractional pixel-edge `xywh`. The two formats have distinct contracts. The native importer accepts detection-only canonical releases, not arbitrary third-party COCO or the Chapter 9 mask archive.

The reader profile requires 1–100 available human-reviewed images, zero or one box per image, exactly one foreground label including a positive image, and nonempty train/validation/test. Whole connected families, fixed source splits, unselected bridges and deleted lineage remain the existing allocator's responsibility. Fractional edges, multiple boxes/classes, all-negative selections and incompatible splits are rejected without rounding, clipping, dropping or reshuffling. A split can lack positives or negatives; preview discloses the resulting coverage limitation.

Images retain their exact normalized source PNG bytes. Same-size L PNG masks use only 0/255 with exclusive right/bottom rectangle edges. They transport reviewed boxes and do not establish segmentation truth. Negative images have an all-zero mask, presence 0 and zero normalized box. The actual reader produces bilinearly resized 96×96 CHW RGB float32, divided by 255; float32 normalized `xyxy` uses original dimensions.

`manifest.json` retains original current annotations, source/target revisions, rights, review, provenance, source/asset/pixel hashes, protected-family context, assignments and derived-target/mask hashes. `label_mapping` records the exact current annotation label, generic reader name **foreground object**, reader class index **0**, and positive/negative presence **1/0**. These are distinct from COCO category IDs. The existing canonical writer assigns release-local IDs from the full sorted label vocabulary; those IDs are not global or persistent class identities.

New native canonical admissions retain the exact validated complete COCO `category_table` and original box-ordered `annotation_category_ids` in `provenance.acquisition.declared.upstream`, beside the original record and archive/manifest/COCO hashes. This evidence describes the consumed source, independently of later target relabels or geometry edits. A source category 2 can therefore remain original evidence while a current one-label canonical release uses ID 1 and the Chapter 9 reader uses binary presence. Native categories do not become local annotation IDs or automatic approval. Legacy acquisitions that omitted the table are explicitly marked **unavailable**; IDs are never guessed. Local image acquisitions are marked **not_native**. Native preparation retains its existing 3 MiB decoded-row and 16 MiB combined bounds; extra category evidence can make a near-budget input ineligible.

Before raster work, the adapter checks declared bounds, captures all selected PNG bytes within the aggregate byte budget, and validates every captured header/dimension. Sequential RGB validation, mask construction, preview hashes and the final writer use those same immutable captures. Freeze recaptures under the release owner's lock and checks the exact fresh token. Limits are 40 MP per image, 100 MP selected pixels, and 40 MiB complete logical archive, including images, masks and metadata. Atomic sibling-temporary publication uses fsync/replace; failed projections clean up and preserve existing releases and database state.
