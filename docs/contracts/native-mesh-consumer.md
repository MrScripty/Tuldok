# Bounded native mesh consumer

`NativeMeshDataset` reads modern mesh-only `canonical_v1` frozen releases of the unchanged `tuldok_mesh_v1` ASCII input profile. One complete mesh is one sample. An explicit owner-supplied release SHA256 and train/validation/test split are required; there is no new or changed split allocation, sampling, target inference or training. A nonempty human inspection note is required by this consumer, which is stricter than the existing mesh owner’s empty-note acceptance. A complete declared `protected_components`/`export_group` graph is required, including known deleted/unselected parents and cross-kind bridges. Proofless older packets are refused; create a new release through the owner. Mixed canonical releases remain unchanged and are unsupported by this consumer.

## Exact correction and target reader

The optional target is unchanged plyfile **1.1.3**, exact module SHA256 `b8ac8908306945b4313a53d84665d7affcd467e5be7d03c82bec986220166f45`, official wheel SHA256 `581302f07b1c298431dcaa9038bba2ae80f3f7868b29ccb826a07bc4488ff38a`, with NumPy **2.5.3**. Provision `requirements-mesh-consumer.txt` separately; code never installs dependencies. The same reader pins are retained in `tests/pointcloud-consumer-pins.json` and consumed unchanged by point-cloud QA.

The pinned ASCII `PlyProperty._from_fields` delegates decimal strings to NumPy dtype.type. An accepted float32 token `1.0000000596046448` should round to native bits `3f800001`, while this ASCII reader produces `3f800000`. Token `1.0000001788139343` should also produce `3f800001`, while it produces `3f800002`; negative counterparts disagree similarly. Exact halfway ties agree. Thus universal direct original-ASCII precision compatibility is disproven. Reader parameters mmap/known_list_len do not change ASCII scalar conversion. No tolerance relaxation, reader monkey-patching, input rejection or precision downgrade resolves this here.

The selected correction uses the reader's supported **standard binary_little_endian PLY 1.0** path. The existing Tuldok mesh decoder first rounds exact decimal tokens to their declared native f32/f64 values. Those already-declared native values are packed as little-endian scalar bytes, with each original property's own dtype/order. Faces are ordered `property list uchar int vertex_indices`: count3 plus three native int32 indices. The unchanged actual reader (`PlyData.read(..., mmap=False)`) must return byte-identical native fields and ordered triangles before any sample is exposed. This follows the existing [PLY vertex/property/list model](https://sites.cc.gatech.edu/projects/large_models/ply.html); binary support is verified in the exact released reader source and by actual file read/write tests.

Original ASCII `mesh.ply` and `mesh.json` bytes, hashes, units/frame/provenance and owner record remain authoritative. The derived binary is exact for declared native values, **not source-byte identical** and does not preserve original comments or decimal spelling. Existing mesh decoding canonicalizes native zero to positive zero; original negative-zero spelling remains only in the byte-exact source. Point-cloud signed-zero semantics are separate and unchanged. No coordinates, normals, units, vertex order, face order, winding or connectivity are changed.

## Dataset and outputs

Fields are separate one-dimensional native `x`, `y`, `z`, optional complete `nx`, `ny`, `nz`, and numeric `vertex_indices` with shape `[triangle,corner]` and dtype `<i4`. Coordinates are not promoted into a common Nx3 dtype. Provided normals remain dimensionless, with their magnitudes unchanged. Variable vertex/triangle counts and optional normals require an explicit downstream collator.

Sample metadata retains the complete original row/review/rights/annotation, graph snapshots, release hash/split, declared native properties and their shapes/dtypes, units/frame, actual reader pins, scope and derivation hash/byte count. `write_npz` atomically replaces a bounded pickle-free file containing only numeric fields plus `metadata_utf8` uint8; read with `numpy.load(..., allow_pickle=False)`.

`write_ply` atomically replaces one bounded standard binary file. Standard ASCII comments declare its derivative status, release/bundle/original PLY/original sidecar hashes, record ID/revision/source_revision/split, plus base64 of the **exact ORIGINAL mesh.json**. The embedded original sidecar verifies the original ASCII hash association as source evidence; it does not authenticate the sender; it does not claim to hash the derived binary. A single atomic file prevents geometry/provenance pairing failures. Complete local review, corrected rights and family proof remain in sample/NPZ metadata and the retained original release; standalone binary comments do not replace those owners. This binary output is not accepted by the unchanged ASCII-only Workbench importer.

All release schema/projections, raw-pair hashes and metadata, family graph/allocation and actual reader results for every mesh are validated before admission. Captured release bytes are immutable; each item returns fresh arrays/deep metadata. Output aliases to the input source (including symlinks/hardlinks) are refused. Failed writes/replacements retain the prior destination and remove temporary outputs.

## Limits and evidence

64 whole meshes; 64 MiB physical/logical release; 8 MiB manifest/split metadata; 256 KiB metadata line; depth64 duplicate-free finite Unicode JSON; 5000 known context snapshots; 40 MiB selected raw bundles. Original mesh limits remain 20,000 vertices, 40,000 triangles, 2 MiB PLY, 32 KiB sidecar, 16 KiB header and 1 KiB lines. Derived binary header is at most 64 KiB, complete PLY at most 4 MiB, complete NPZ at most 16 MiB.

Tiny authored/source-derived analytic fixtures cover positive/negative midpoint neighbors and ties, subnormals, mesh native-zero policy, mixed coordinates/normals, ordered topology, exact original provenance, malformed/hash/truncation/nonfinite/graph controls, and atomic failures. Independent reader QA uses actual binary files and external write/read roundtrips. Chromium QA preserves unchanged mesh UI ownership/review/rights behavior and transfers original raw pairs between two actual owners before their own frozen release/consumer outputs. Those original Chrome downloads, consumer derivatives and checker-owned secondary data are counted separately.

Geometry and data-preparation compatibility are qualified; scientific/physical correctness, watertightness, normal correctness, material calibration, targets, inference, training and model quality are not. The mesh rounding mismatch is resolved by this explicit native-value binary interchange choice, not by declaring original ASCII universally compatible.
