# Bounded human-authored polygon instance segmentation

`image_segmentation` extends the existing image Dataset/Workbench and canonical release owner. Its concrete consumer is actual pycocotools2.0.11 mask decoding and torchvision0.23.0 `CocoDetection` reading. This slice qualifies authoring, import/export and reader compatibility. It does not define a training objective, instantiate a model, run evaluation/training or establish semantic target quality. UI remains provisional.

## Targets and geometry

The closed annotation is `{"instances":[{"label":"object","points":[[x,y],...]}]}`. A record has0–100 instances, each single simple ring3–128 distinct vertices, at most1,024 total vertices. Closure is implicit; repeating the first vertex is refused. Labels use the existing trimmed1–80 Unicode code-point semantics. Coordinates are finite JSON integers/floats in the oriented image pixel-edge rectangle `[0,width] × [0,height]`; booleans, overflow and nonfinite values are refused. Original accepted numeric primitives, signed zero, vertex order and winding remain intact in source targets and provenance.

Exact `Fraction` predicates over the supplied integers/binary floats reject zero-length/repeated vertices, adjacent backtracking/overlap, crossing and nonadjacent touching. Shoelace area must be representable as a finite positive float; underflow to zero is refused. Concave rings, clockwise/counterclockwise order, forward collinear vertices, edge vertices, overlap between objects and repeated labels are supported. Same-label duplicate rings are refused under rotation, reversal and numeric int/float/signed-zero equivalence, without rewriting evidence. Holes, multipart instances, crowds, RLE, arbitrary foreign COCO, semantic masks and video/tracking are outside this profile.

Only explicit local `human_reviewed` segmentation is export eligible, including zero-instance negatives. Drafts and programmatic verifier grants are refused. A valid positive ring that rasterizes to zero pixels remains a positive instance, distinct from an explicitly reviewed empty list. Human labels and rights notes are separate from original provenance, producer truth and authenticated reviewer identity.

## Authoring and ownership

The task selector, SVG outline and instance list share the existing editor. Primary pointer capture requires exact current owned source URI/revision, loaded natural dimensions, pointer ID and an idle annotation/rights editor. Coordinates are native fractional pixel edges, never rounded, clipped or changed into masks. Tiny sources enlarge with preserved aspect ratio and a matching overlay. Pointer-down advances editor intent and blocks older Open adoption; active capture joins discard/unload guards. Cancellation adds no vertex. Unfinished numeric text requires explicit Add or Clear and blocks Save. Changing task requires deliberate discard when pending capture/text exists.

Unchanged rendered Save and numeric entry preserve integral-float and signed-zero coordinate primitives. Structured JSON parse source tokens are attached to exact target objects and carried only into their adopted editor copies; task/source replacement drops ownership. Only strict finite JSON number tokens matching the exact current coordinate (including signed zero) may be emitted at point positions. Labels and all other values retain ordinary safe JSON serialization. New pointer coordinates generate their own numeric representation. This requires browser JSON parse source support; unsupported browsers refuse positive-source adoption rather than normalize coordinate evidence.

Save/reopen and human review remain separate actions using exact record/source CAS and existing history. Lost acknowledgement retains local intent; repeated stale Save cannot create another revision. Late save/rights responses respect newer editor intent. Native admission, rights correction, exact named selection, stale preview, frozen releases and recovery retain their existing owners. Source families, fixed splits and unselected/deleted bridges remain indivisible; neither rings nor pixels create independent split records.

## Canonical release and native import

Canonical export uses the existing manifest, normalized PNGs and split COCO/typed JSONL files. Detection and polygon tasks share the exact Unicode-sorted release-local category table1..N across all three splits. IDs are not a persistent taxonomy. Polygon COCO targets use `segmentation: [[x0,y0,...]]`, `iscrowd: 0`, continuous `[min_x,min_y,max_x-min_x,max_y-min_y]` bbox and continuous shoelace area. Image and annotation IDs retain existing ordering. Other typed tasks retain their JSONL projection. The polygon coordinate/area statement is appended only when a segmentation record is selected, including all-negative selections. Detection-only serialization retains the old exact statement and bytes.

Segmentation-bearing selections have at most100 total records,100 million selected image pixels and40MiB complete logical serialization (including duplicate manifest/typed rows) and stored ZIP bytes. Count/pixel/source-byte preflight precedes image decoding; actual PNG header dimensions are checked before RGB conversion/load. Hash and archive streams count bytes against the selected source sizes, rejecting growth before further hashing/writing. Preview and writer share exact serialization; final stored size is checked before atomic replacement. Failures leave existing releases and records intact.

The existing native canonical adapter accepts polygon-only or detection/polygon mixed packets, not arbitrary other mixed canonical tasks. Bounds remain8MiB physical ZIP,16MiB expanded,1–100 records,3MiB decoded signed row,16MiB prepared total and40MP/image; polygon-bearing packets add100MP summed pixels before PNG decoding. Strict finite/duplicate-key JSON, complete files/hashes/PNG dimensions/pixels, exact coordinate statement, simple rings, shared categories, ordered IDs and target/COCO associations are checked before admission. Declared polygon review must be human; every local import still starts with a new ID, draft review and unknown rights. Exact upstream record, category table and target-ordered category IDs remain declared source evidence. Local rights correction does not overwrite original unknown-rights provenance. Dataset owns atomic image storage/acquisition; duplicate pixels, source-family split conflicts, overflow and bad markers are refused. Read-only receipt lookup reconciles uncertain admission, and a new deliberate retry uses existing duplicate refusal.

## Consumer identity and raster semantics

`tests/fixtures/polygon-consumer-pins.json` pins official [mask.py](https://github.com/ppwwyyxx/cocoapi/blob/ac87f5077ad6b8864c2dc5e93d14cae62d1db05a/PythonAPI/pycocotools/mask.py) at `ac87f5077ad6b8864c2dc5e93d14cae62d1db05a`, installed `coco.py`, `mask.py`, retained Linux abi3 `_mask` extension bytes and torchvision `datasets/coco.py`. The retained wheel is411,685 bytes, SHA256 `a82d1c9ed83f75da0b3f244f2a3cf559351a283307bd9b79a4ee2b93ab3231dd`; its extension is1,363,024 bytes, SHA256 `fd22099149a494c583e60be648924a71d51a46add9f2f112d695c89434e772de`. Exact installed identities are checked at execution. Source identity is not a claim of reproducible wheel compilation; other compiled platforms need their own reviewed pins. No production dependency or model package is added by this feature.

The independent archive/ring oracle checks the exact coordinate contract, original primitive-preserving targets, full associations/hashes and the supplied declared selected-family graph before permissive COCO indexing. It then executes `frPyObjects`/merge/decode and `annToMask`, confirms equal uint8 binary height×width masks, separately inspects raster area/bbox, and reads actual PNG/annotation pairs through `CocoDetection`. Continuous area and raster pixel area are different measurements. There is no COCO evaluation/metrics or trainer admission; `loadRes`, downloads, `iou`, models and optimizers are forbidden in this QA path.

Reader QA limits are separately stricter:8MiB archive,16MiB expanded,100 records,4,096 pixels per axis,100MP total image pixels and100MP counted decoded-mask work, including both complete decodes per polygon. All declared work is checked before actual mask calls; box-only annotations are skipped by mask decoding. Application40MiB output bounds do not promise acceptance by the stricter native/QA profile.

## Evidence basis

The fixture reuses six retained authored16×12 RGB images, paired by fixed train/validation/test families. Manually authored rectangle, fractional concave L, triangle and tiny rings have continuous areas16,14.25,8,0.015625 and independent hand-specified raster pixel counts16,20,6,0. There are12 positive rings and three separately reviewed negative images. Observed decoding corrected the initial tiny-ring assumption; a larger0.0625-area candidate actually decoded one pixel. The corrected fixture keeps geometry/decoder acceptance unchanged. Automated human-review clicks are QA simulation, not an authentic labelled benchmark or semantic truth.

Fresh unit coverage includes malformed hashes/truncation/axes/contracts/nonfinite values, exact primitive evidence, all-negative contracts, geometry/count/byte bounds, predecode actual headers, counted streams, category/association/family violations and atomic annotation/import/release failure. Actual reader coverage includes source, native roundtrip and mixed box/polygon files. Chromium coverage includes a clearly labelled controlled HTTP1.0/-0.0 target seed plus unchanged rendered Save/reopen/review and numeric-entry primitive proofs, then restoration of the original12-instance fixture; clean pointer-down versus old Open, cancel/owner/busy guards, draft/pending/task/review/rights/acknowledgement recovery, exact saved-set reload, native second-owner provenance and local rights/draft/reopen/review, stale selections and immutable release bytes. Rendered anchors produce actual Chromium disk ZIP downloads consumed by the pinned reader. These tests qualify transport/workflow within their declared limits, not trained segmentation or data quality.
