# Native simulation import and inspection

The adapter preserves complete accepted-state trajectories under exact historical Rheon snapshots: v1 `fee7b4a139574f87b259796b1ba8698a41d31ac1` (draft PR20 when read) and v2 `020437fa638ad56823b544ba1f9207ceef065f12` (draft PR32 when read). No merge or automatic repin is assumed. [V1 source](rheon-v1-source.json) and [v2 source](rheon-v2-source.json) retain upstream paths/blob identities, validator hashes and the sole v2 dependency import-alias adaptation.

V1 requires unchanged `run.json` and `frames.jsonl`; v2 additionally requires unchanged `controls.json`. Validation checks complete hashes/byte counts, fixed geometry/configuration, native axes/shapes/types/units, finite numbers, canonical decimal-u64 stamps, accepted intervals and diagnostic associations before source, record and initial history are published in one Dataset transaction.

The case is16×8×4 cells, constructor0 plus8 accepted steps,9 frames. Run/controls each64KiB; frames2MiB; JSONL line256KiB; HTTP base64 envelope3MiB; selected raw bundles40MiB. Each record is one whole trajectory. Raw ZIPs contain exactly the two/three original files. Separate MAC face velocity components stay f32; tracer stays f32 appearance data; fraction/pressure stay f64. Pressure is the last accepted interval projection; constructor0 has no preceding interval. No images, centered vectors or flattened time are produced.

V2 controls have8 frame-ending interval declarations bound to exact original frames, adjacent stamps/times and run members. Producer origin remains a wire declaration. [Authored v1 controls](sequence-interval-controls.md) are a separate inspection attachment and never become stored producer output. Source-derived v2 fixtures are explicitly synthetic; compatibility does not grant original producer-packet acceptance.

Imports start as drafts with unknown rights by default; the API also permits explicit user-declared rights notes. Existing annotation/source revision checks, rights-note correction, history and separate human review remain owners. Derived trajectory/constructor-family groups cannot be removed. Related selected/unselected/deleted lineage participates in whole-family allocation. A fixed-case train-only release does not establish independent training/evaluation data.

Folder acquisition accepts at most32 trajectories/96 files/40MiB raw files, one flat directory per trajectory and strict v1 pairs/v2 triples. Preflight validates the roster before reading; each item uses the same bounded adapter and commits independently. Earlier successes remain if a later item fails. Stop prevents the next admission; uncertain responses pause without automatic replay. Receipt lookup is read-only.

Single-probe inspection accepts96KiB request JSON/64KiB authored controls, revalidating original bundle/index under exact revisions. Native review has a separate 4KiB request/128KiB response, at most 144 samples per plane and 1296 plane values across nine frames, plus a nine-value native-index time trace. Named native indices/offsets/units/values/time/stamps remain explicit. Inspection does not change source or approve targets.

[Workflow](../trajectory-workflow.md), [human targets](sequence-temporal-labels.md) and [numerical consumer](native-sequence-consumer.md) describe current use. Whole trajectories or explicit contiguous windows retain their original split, native fields and separate human coverage. Atomic NPZ is bounded and pickle-free. An actual training objective and meaningful independent physical families remain inputs; provenance variants/windows do not provide diversity, science or model quality.
