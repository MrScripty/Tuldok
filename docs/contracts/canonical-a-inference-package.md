# Canonical scalar A inference package

This is an explicit private QA profile, separate from the classifier and the two
historical scalar A nominations. It does not enable arbitrary extension entry
points. Preparation creates inert ordinary recipe material; the owner must grant
and admit packaging and the separate captured CPU consumer. Source training,
independent numerical acceptance and physical acceptance remain separate.

## Acyclic inference authority

`examples/extensions/field-surrogate/v3-canonical/infer.py` is frozen at SHA256
`15f6bc0da835f4a3f8a54a2abf0552e8a0b6c69a1ac2e6baceebb9288a0b8b15`.
`inference-contract.json` is frozen at SHA256
`d60b93699f978c125a567734ef4d610cb4027b3b2f047c31e6d579677121da1d`.
The literal adapter is `example.scalar-a.canonical:inference`, revision1, with
contract format `canonical_scalar_affine_inference_contract_v1`.

The contract pins exact producer, captured SDK, original authored source,
independent oracle and notice bytes, plus the five exact semantic contribution
declarations. It fixes architecture, field interface, stage `train`, geometry,
gauge, task and evaluation profile. It excludes recipe/provider/contract hashes
from the numerical source authority. The contract pins the inference source;
the outer immutable Model, composition and package pin the entire actual source
closure including the contract, inference source, provider and recipe. Adding
the inference files to the provider and recipe therefore creates no hash cycle.

The standard-library function remains
`predict(initial_npy, weights_npy, transform_npy, request) -> prediction_npy`.
The request has exactly `format`, `policy` and `sha256`; its format is
`scalar_affine_inference_request_v1`, its policy is the frozen contract policy,
and its three raw-file hashes name `initial`, `weights` and `transform`.
The consumer derives those hashes from the selected descriptor, descriptor-bound
fitted transform and permitted fixed-probe input. A probe payload hash is a
different identity from a complete NPY file hash.

`initial_scale` and `initial_offset` are closed finite [-1,1] Model controls for
training initialization. Their actual values stay bound to the published Model
and admitted policy. Reconstruction uses only the selected retained learned
weights, retained training mean/population standard deviation and permitted
initial input. It never trains, reads a provider, refits a transform or uses the
initialization controls as learned state.

## Existing bounded execution seam

For this profile only, `request.json` is a declared captured source with its
whole SHA in the immutable recipe/Model/grant. The worker accepts the single
literal `--request-from-source request.json` and reads beside its captured entry
file. The closure plus31 exact Run artifact inputs therefore occupy exactly32
inputs. Historical request-as-input layouts are unchanged; runtime/input/file
bounds are unchanged. Both the new canonical packaging operation and its fresh
consumer select the explicit captured CPU snapshot.

The portable snapshot manifest SHA identifies the captured file inventory. The
composition runtime reference instead hashes the complete canonical descriptor,
including its catalog and root. These identities are checked separately: the
source execution descriptor must exactly equal the package descriptor, and the
composition requires its full `kind`, catalog, descriptor ID and descriptor SHA.

The fresh receipt remains `fresh_field_inference_verification_v1`, with exact
adapter and contract SHAs identifying this distinct nomination. Its fixed-probe
reconstruction tolerance is absolute `1e-10` plus relative `1e-10`; numerical
acceptance stays `not_evaluated`. Successful reconstruction establishes no
model-quality, generalization, physical-validity or resume claim.
