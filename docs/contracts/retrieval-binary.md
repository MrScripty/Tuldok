# Reviewed binary relevance v2

This bounded local data-preparation profile uses task `text_retrieval_binary` and export `text_retrieval_binary_v2`. Positive-only `text_retrieval` / `text_retrieval_v1` retains its target and three-file consumer schemas. No mesh or point-cloud parser changes are involved. Review/rights/history, immutable source text, exact selections and the existing family allocator remain the owners.

Documents have `{role:"document",note}`. Queries have `{role:"query",note,judgments:[{document:{id,revision,source_revision},relevance}]}`. Relevance is exactly `relevant`, `not_relevant`, or `unjudged`. A query has one to thirty unique document references; zero positive and all-unjudged queries are supported. All omitted relations remain unjudged. No arbitrary grades, inferred negatives, implicit pairs or automatic review.

Every listed relation, including explicit unjudged, must reference an immutable query parent that is a current available separately human-reviewed binary document. Notes are nonempty, at most 4,000 Unicode codepoints. Source and record revisions are exact positive signed-64-bit integers; browser revisions must be JavaScript safe integers. Save and publication recheck references. Editing/deleting a document refuses old query Save/preview/freeze until the source is available and the user deliberately replaces its reference. Former parents remain immutable family ties after a judgment is removed.

Raw query admission `/api/workbench/retrieval-binary-query` accepts exactly `name`, `text`, `groups`, `rights`, `judgments`, within 1 MiB. It requires reviewed referenced documents and creates a raw unannotated draft under the default text-classification task, retaining declared judgments as unreviewed acquisition evidence. Choose the binary task, inspect/author the target, Save/reopen, then separately review.

V2 release requires at least one document and query, every referenced document explicitly selected, and one family split for all listed relations. Existing connected graph allocation includes current/former parents, unselected/deleted bridges, duplicate source ties and groups. Fixed source splits cannot be overridden. No minimum positive count, mandatory three populated splits, ranking objective or training pairs are imposed.

The comment-free stored ZIP contains `manifest.json`, exact canonical NFC/LF `assets/<id>.txt`, `corpus.jsonl`, `queries.jsonl`, `judgments.jsonl`, `qrels.txt`, `README.txt`. Records and relations use sorted record order; query judgment order is retained. Corpus rows are `doc_id,text,group,split`; query rows are `query_id,text,group,split`. Typed judgments bind exact `query` and `document` revision objects plus `relevance,group,split`. Split names remain train/validation/test. Qrels use four whitespace-separated TREC fields: `query_id 0 document_id grade`, mapping relevant=1, not_relevant=0, explicit unjudged=-1. Omitted relationships emit no qrels row. Typed judgments/manifest preserve semantics and revision/family information absent in qrels. This profile does not qualify a downstream evaluator's treatment of -1 or a trainer's implicit negatives.

`manifest.json` has schema_version2, exact scope/limits, selected full record snapshots with review/rights/provenance, protected component snapshots and lineage, frozen assignments/existing allocation report, state counts, exact projection/asset hashes. Preview token includes all target/source/family/scope/file evidence. Existing atomic release publishing rechecks source/targets and removes temporary files on failure; frozen bytes remain unchanged by subsequent edits.

Limits:128 selected records,30 judgments/query,200,000 source text codepoints,8 MiB complete logical archive including duplicated text/metadata,5,000 supplied context snapshots. Native import accepts at most9 MiB physical/8 MiB logical stored ZIP,134 unique safe members,JSON depth64 and13 MiB HTTP envelope. No compressed/encrypted/ZIP64/multi-disk/extra/commented archives, unknown members, duplicate/nonfinite JSON, malformed hashes or truncated packets. Whole-file SHA256 is required; a co-supplied hash verifies bytes without authenticating the sender.

`/api/workbench/retrieval-binary-import` takes exactly `{archive:<base64>,sha256:<lowercase hex>}`. Complete source/target/schema/known-family/allocation/projection/qrels validation precedes one atomic bundle transaction. All new IDs are remapped; new local documents and queries retain draft annotation/history and unknown rights. Original full records, rights/review claims, sender IDs and family/split remain upstream provenance, not local approval. Selected parents map to new local IDs; unselected upstream ties survive as protected origin anchors. Human review of local documents increments their revisions; then deliberately refresh each query's exact document refs, Save a draft, reopen and review. Native import never approves relevance.

Each selected family member receives the same protected domain-separated anchors for every supplied upstream member ID, parent ID and original group. Existing origin anchors propagate unchanged across subsequent transfers. The complete anchor set must fit the existing thirty-group bound; overflow refuses the whole import, with no dropped lineage. An owned immutable import-binding table preserves source split and anchors across task edits/deletion. Missing/corrupt bindings mark lineage unknown and block related release; ordinary Save cannot remove anchors. Supplied graph validation establishes declared known closure, not authenticated upstream completeness or semantic independence. Generic snapshot readers accept retained fixed text splits and known deleted text bridges; v1 positive target/file schemas remain unchanged.

QA uses tiny authored fixtures and simulated review clicks. The compatible external reader is released ir_measures0.4.3: exact verified `Qrel` and `read_trec_qrels` definitions are source-loaded unchanged from its released util.py with stdlib-only dependencies. The full package/provider/metric pipeline is not imported. Pinned released wheel/module/definition hashes live in `tests/fixtures/retrieval_binary_consumer/pins.json`. Actual file parsing retains1/0/-1; full closed source/revision/family transport is separately validated. No ranking, metrics, model loading, inference or training runs, and no semantic, permission or model-quality qualification is claimed.
