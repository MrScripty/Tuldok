# Whole-trajectory dataset workflow

This is the supported local workflow for native sequences. The UI remains provisional. It imports retained evidence and authors human judgments; it does not run Rheon or train a model. The [remaining feature map](remaining-feature-map.md) separates this bounded workflow from broader training-data capabilities.

1. In **Import simulation sequence**, choose the original `run.json` and `frames.jsonl` files. A supported v2 bundle also requires its unchanged `controls.json`. Keep actual and synthetic sources explicitly named. Inspect the import receipt and collection: a new record is a draft with no annotation. A rights note is declared metadata, not permission inferred by import.
2. Open the record from the collection. The original bundle, manifest and nine-entry frame index are inspectable. In native trajectory review, choose a named field, native index and plane, then explicitly Load. Native shapes, f32/f64 interpretation, units, offsets, positions, time, hashes and stamps remain visible. Frame navigation uses the loaded trajectory locally. Constructor0 has no preceding accepted interval; pressure describes the last accepted interval projection. Inspection does not label or review the record.
3. Enter a whole-trajectory note. In **Human-defined temporal labels**, choose inclusive first/last native frames, your own label and a rationale, then **Add draft range**. Edit/Remove/Clear operate on staged labels. Pending controls must Add/Update or Cancel before Save. An explicit inspection-reference append is also only a draft note. Neither action changes numerical fields, controls or producer provenance.
4. Save the draft, reopen it and inspect the saved ranges. Separately choose **Human reviewed** and Save after checking this exact content. Target edits reset the review choice to draft. Save checks annotation/source revisions; a conflict requires deliberate reload instead of silently replacing newer targets. History retains prior committed states.
5. Select the desired reviewed whole records using collection checkboxes. **Save selected records as a new set** preserves exact IDs and annotation/source revisions. A search/filter is a dynamic collection view, not set membership. Clear the transient selection and **Open fixed selection** to restore the saved references, including members hidden by the current filter. Reloading its `#selection=ID` URL reopens that set without restoring an export proof.
6. Choose canonical export and split targets, then **Preview selected release**. Check exact selected revisions, review/rights warnings, family closure and requested versus achievable splits. The retained actual/synthetic fixed-case corpus shares one initial family: train/test or train/validation/test requests are refused. An explicitly train-only release demonstrates packaging, not independent training/evaluation data. Unselected relatives protect allocation without becoming selected exports automatically.
7. Freeze only after an eligible fresh preview. Download the immutable ZIP: typed manifest/JSONL records retain human targets beside the original raw bundles, with all native frames and source/endpoint hashes/time/stamps. Related selected trajectories stay in one split; frames are not separate examples. Later edits do not change frozen bytes. Reopening an old fixed set after a label edit retains its old references and blocks release until current revisions are deliberately selected.

Current bounds: one complete fixed16x8x4 trajectory with constructor plus8 accepted steps (nine frames); original manifest and optional controls each64KiB, frames2MiB and JSONL line256KiB. Temporal targets have at most16 ranges within0..8, label80 Unicode code points, required rationale500, whole note4000 and full canonical annotation64KiB UTF8. See the [target contract](contracts/sequence-temporal-labels.md), [simulation import contract](contracts/simulation-sequences.md) and [v2 source pin](contracts/rheon-v2-source.json).

The joined [browser qualification](../tests/browser_trajectory_workflow.cjs) uses rendered UI writes against production HTTP/SQLite, original retained actual v1 bytes and explicitly source-derived synthetic v1 fixtures. It checks import → native fields/time → labels → draft/reopen/review → exact set/filter/reload → preview/freeze → owned app-only restart → durable targets/references/raw export → later draft/stale set/immutable release, with independent ZIP checks and desktop390px artifacts. Its network ledger distinguishes mutating UI requests from read-only inspection/preview POSTs and observer GETs. V2 controls remain covered by separate registered gates using synthetic evidence; source-derived fixtures do not grant original producer-packet acceptance. Qualification does not establish an authenticated reviewer identity, scientific validity, a consumer taxonomy or model quality.

After download, use the [native numerical consumer](contracts/native-sequence-consumer.md) with the exact release hash and explicit split to inspect whole native arrays or export an explicit contiguous-window NPZ. Human coverage and field/time/source evidence remain separate. New sequence-only exports include declared-family context; window sampling never creates independent split examples.
