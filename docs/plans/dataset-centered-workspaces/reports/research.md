## What current Tuldok actually owns

All following links are pinned to inspected main:

- [app.py](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/app.py), [workbench.py](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/workbench.py): Dataset image/corner authority, Workbench generic record/review/history owner and HTTP composition. `TASKS` contains image detection/classification/caption, text classification/entities/corpus, sequence transport and mesh geometry. Query kinds are image/text/sequence/mesh; no audio kind or editor. Root remains book-corner UI; `/workbench` provides generic data work.
- [saved_selections.py](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/saved_selections.py), [saved_searches.py](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/saved_searches.py), [dataset_releases.py](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/dataset_releases.py): fixed revision pairs differ from live queries; previews inspect without creating a release; create checks selection and preview token. Connected-family allocation and frozen bytes already exist. Preserve unselected bridges, deleted/legacy relatives and multi-parent records.
- [image_classification_export.py](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/image_classification_export.py): `image_classification_v1` maps canonical validation to `val`; safe synthetic folder names preserve exact labels in manifest/vocabulary. The specific consumer requires two or more classes and nonempty per-class coverage in all splits. It reports blockers rather than dropping or silently moving records.
- [actual-reader check](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/tests/check_image_classification_consumer.py), [trainer fixture](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/tests/fixtures/train_image_classifier.py): check pins reader and trainer hashes, uses Torch 2.8.0/torchvision 0.23.0, and actually invokes a one-epoch scratch CPU TinyCNN, checkpoint reload and test evaluation in the test procedure. Its six solid images prove consumer compatibility, not quality. The fixture's header says syntax-checked, but the current checker explicitly executes it; this task inspected that code without rerunning it. The production app has no equivalent first-class Runs/training UI. The fixture uses 96×96 resize/ToTensor, `metrics.json` and `best.pt`; per-example predictions and run lifecycle must be added in the production adapter. M2 preserves the pinned fixture as an independent historical oracle.
- [CI](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/.github/workflows/tests.yml) installs CPU Torch and torchvision plus scikit-learn 1.7.2 and an extensive instruction-consumer environment for existing tests. Do not turn that full verification environment into base app requirements. A minimal optional image runtime needs its own qualified dependency closure. The current training-bearing aggregate is deliberately not executed in this planning task.
- [text_corpus_export.py](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/text_corpus_export.py), [preferences.py](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/preferences.py): existing reviewed task-specific exports are reusable. Entity code-point offsets over NFC/LF text must not be imposed on exact-string response/preference contracts; preference outcomes require explicit judgments.
- [static mesh contract](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/docs/contracts/static-mesh.md): bounded ASCII PLY triangle meshes, original mesh/sidecar bytes, declared units/frame, whole-geometry human review, sampled XY/XZ/YZ inspection; no binary PLY, general point clouds, textures, arbitrary polygons, simulation or training claim.
- [Rheon contract](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/rheon_sequence_contract.py): exact 16×8×4 grid, nine frames and named staggered fields under a pinned producer contract. Whole trajectories remain protected. This is not general volume or animation authoring.

## Primary product research: patterns, not dependency compatibility

| Primary source, verified 2026-10-11 | Observed pattern | Proposed use and limit |
| --- | --- | --- |
| [FiftyOne Enterprise Annotation Workflows](https://docs.voxel51.com/enterprise/workflows.html) | Visual stages route annotate/review tasks; rejected work can return for correction. Individual samples open in annotation/review modes with workflow context. | Keep pipeline orchestration distinct from record editing. Our first execution DAG is acyclic; corrections return through a new data revision. This does not establish an open-source FiftyOne feature, library API or Tuldok compatibility. |
| [Label Studio labeling configuration](https://labelstud.io/guide/setup) | Configuration separates data objects, annotation controls and visual layout; changing labels/types on annotated projects has constraints. | Version modality/task schema independently of presentation; preserve old annotations during schema changes. Do not embed arbitrary XML or claim Label Studio import compatibility. |
| [Argilla annotation UI](https://docs.argilla.io/latest/how_to_guides/annotate/) | Focus/bulk views, draft/submitted states, filters and keyboard controls; two-column and compact layouts serve different tasks. | Build focused review and accessible compact controls; proposals stay separate from accepted labels. No Argilla dependency required. |
| [Roboflow dataset versions](https://docs.roboflow.com/datasets/versions/dataset-versions/create-a-dataset-version) | Versions freeze images, labels, preprocessing and augmentation; subsequent project edits do not mutate prior versions. | Train/run against immutable releases. Keep Tuldok's stronger existing connected-family rules; do not copy rebalance behavior blindly. |
| [KNIME components](https://docs.knime.com/ap/latest/analytics_platform_components_guide/) | Reusable components have configuration and output views; copied versus linked components have different update behavior. | Begin with pinned named recipe versions; explicit upgrades rather than mutable linked behavior in historical runs. No component framework before real reuse. |
| [Azure Designer v2](https://learn.microsoft.com/en-us/azure/machine-learning/concept-designer?view=azureml-api-2) | Drag/drop assets and custom components; pipeline drafts and jobs are distinct; classic v1 and custom v2 components cannot mix. | Separate draft graph from run; make typed/versioned compatibility visible. No Azure service, deployment or SDK dependency proposed. |

## Pantograph: inspected producer, unproven integration

Fresh source clone HEAD: `256b6b94ece4dbbaa1fb236bc4092ad08aa63525`.

- [Headless contract](https://github.com/MrScripty/Pantograph/blob/256b6b94ece4dbbaa1fb236bc4092ad08aa63525/docs/headless-workflow.md) identifies canonical Rust `pantograph-workflow-service`, application-lifetime runtime, backend definitions, preflight, sessions, submit/status/artifacts, close and shutdown. It explicitly acknowledges direct/binding paths still being removed and packaging/platform compatibility not yet release-grade.
- [Workflow DTOs](https://github.com/MrScripty/Pantograph/blob/256b6b94ece4dbbaa1fb236bc4092ad08aa63525/crates/pantograph-workflow-service/src/workflow/contracts.rs) define workflow ID/semantic version, node/port value bindings, output targets, runtime requirements and typed capabilities. Arbitrary `serde_json::Value` at a transport field is not a proof of semantic modality compatibility.
- [Graph sessions](https://github.com/MrScripty/Pantograph/blob/256b6b94ece4dbbaa1fb236bc4092ad08aa63525/crates/pantograph-workflow-service/src/graph/session_types.rs) own revision-bound connection/edit requests and undo/redo. [Scheduler contracts](https://github.com/MrScripty/Pantograph/blob/256b6b94ece4dbbaa1fb236bc4092ad08aa63525/crates/pantograph-workflow-service/src/scheduler/contracts.rs) distinguish queue and active-task cancellation. Neither by itself proves Tuldok restart/resume semantics.
- [Svelte graph package](https://github.com/MrScripty/Pantograph/blob/256b6b94ece4dbbaa1fb236bc4092ad08aa63525/packages/svelte-graph/package.json) is `0.1.0`, source exports with Svelte `^5.0.0` and `@xyflow/svelte ^1.5.0` peers. Reusing it changes Tuldok's frontend toolchain and does not embed the Rust executor.
- [Frontend HTTP adapter](https://github.com/MrScripty/Pantograph/blob/256b6b94ece4dbbaa1fb236bc4092ad08aa63525/crates/pantograph-frontend-http-adapter/src/lib.rs) explicitly separates frontend URL proxy integration from headless APIs. It is not evidence of an available generic REST server or Python binding. A generic allowlisted process node also does not establish a trainer's checkpoint, prediction or cancellation contract.

S1 must prove one real no-model host path before permanent reuse. Prefer one owner for graph validation/execution; do not implement both Pantograph and a parallel local general engine. Retain a small fixed local DAG if the reuse cost/boundary cannot meet the first slice.

## Pumas: inference contracts, not training

Fresh source clone HEAD: `ad31e391dcd94c204b3fcd748cc98d27b3281e65`.

- [Model operations v1](https://github.com/MrScripty/Pumas-Library/blob/ad31e391dcd94c204b3fcd748cc98d27b3281e65/docs/contracts/model-operations-v1.md), [producer types](https://github.com/MrScripty/Pumas-Library/blob/ad31e391dcd94c204b3fcd748cc98d27b3281e65/rust/crates/pumas-rpc/src/handlers/model_operations/types.rs): selected alias/profile, capability/input/output/options bounds and finite/streaming outcomes. Capability is a current observation, rechecked at admission. Request IDs correlate and do not make retries idempotent. Preserve `not_admitted` versus `unknown` and no automatic replay after uncertain effects.
- [Current image-to-text contract](https://github.com/MrScripty/Pumas-Library/blob/ad31e391dcd94c204b3fcd748cc98d27b3281e65/docs/contracts/image-to-text-v0.8.md) and [Tuldok consumer](https://github.com/MrScripty/Tuldok/blob/1bb2c3ae9d08432c53ddf9d4bf77fa5f62ad318c/docs/contracts/pumas-image-to-text-consumer.md) refine older generic capability documentation. Reuse qualified Tuldok inference adapters and exact DTO pins; don't infer available tasks from modality names alone.
- [Installed audio session](https://github.com/MrScripty/Pumas-Library/blob/ad31e391dcd94c204b3fcd748cc98d27b3281e65/docs/contracts/installed-audio-session.md) and [serving implementation](https://github.com/MrScripty/Pumas-Library/blob/ad31e391dcd94c204b3fcd748cc98d27b3281e65/rust/crates/pumas-rpc/src/handlers/serving.rs) keep shipping admission closed and expose a separately explicit local Cohere experiment with `experimental:true`, `production_available:false`. That cannot be promoted to supported ASR by Tuldok. [Owned transport](https://github.com/MrScripty/Pumas-Library/blob/ad31e391dcd94c204b3fcd748cc98d27b3281e65/docs/contracts/owned-audio-transport.md) retains byte/process custody; cancellation/EOF is not native cessation.
- Audio declarations distinguish sample frames per channel, encoding, rate and channels; conversion must actually resample/downmix, not relabel. A text transcript does not establish timestamped segmentation. The proposed audio dataset workflow works without this inference adapter.

No inspected Pumas API or Pantograph contract establishes an image/text/audio/3D training service. The first trainer is a dedicated Tuldok adapter against an explicitly pinned local consumer. Any later external training integration must separately prove admission, artifacts, lifecycle, environment and per-example mapping.
