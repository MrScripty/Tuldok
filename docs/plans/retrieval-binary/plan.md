# Reviewed binary relevance plan

Base: preserved `b14c2d3d383b65920e33eb3506b04ad3e243ca59`; separate local feature branch. Main remains frozen at `2fc4a46f12d73a0fa467d5482f68edb83d6df6af`. No remote credential retries or publication routes.

Introduce task `text_retrieval_binary` and release `text_retrieval_binary_v2`. Leave positive-only task/export `text_retrieval` / `text_retrieval_v1` intact, including its existing consumer and constraints. Do not alter mesh/point-cloud modules.

Documents carry `{role:"document",note}`. Queries carry `{role:"query",note,judgments:[{document:{id,revision,source_revision},relevance}]}`. Relevance is exactly `relevant`, `not_relevant`, or `unjudged`; one to thirty unique exact document references are required, including explicit unjudged references. Every referenced document must be an immutable parent, currently available and separately human-reviewed under the binary task. Save/review/export refuse stale revisions, deleted/missing/wrong-role references. Nonempty review notes and separate local human review are required; imported judgments are drafts. No arbitrary grades, inferred negatives or automated approval.

All selected documents and queries remain exact NFC/LF sources. Export requires every explicitly referenced document selected. Every declared relation, including unjudged, connects query/document through existing immutable parents; retained former parents, unselected/deleted bridges, duplicate sources and groups participate in the existing allocator. No relation can cross a family split. A zero-positive query is supported; there is no training-positive count or mandatory three-split coverage. Existing allocator validates requested active splits.

The stored ZIP contains `manifest.json`, source `assets/<id>.txt`, `corpus.jsonl`, `queries.jsonl`, `judgments.jsonl`, `qrels.txt`, and `README.txt`. Typed judgments bind exact query/document revision pairs. TREC qrels encode relevant=1, not_relevant=0, explicit unjudged=-1; omitted relationships have no row and remain unjudged. External reader qualification must preserve these three integer values; it must never run metrics/ranking or pass this file to a trainer. Manifest and typed judgments remain semantic authority if an external reader does not support -1. Pin actual external source/package bytes before qualification; do not invent a parser schema.

Initial profile bounds: 128 selected records, thirty refs/query, existing 200,000 text codepoints, 8 MiB complete logical ZIP bytes. Import accepts an exact hash-verified stored ZIP up to 9 MiB physical / 8 MiB logical, 134 members, bounded duplicate-free finite JSON/depth64 and at most 5,000 declared context snapshots. HTTP import envelope 13 MiB. These are a new bounded profile, not a reduction of v1 limits.

Design refinements: each release needs at least one document and one query; queries may have no positives. All projections/qrels and exact closed file/schema membership must be reconstructed at import, and all refs checked again at publication. Validate the supplied known graph without claiming externally authenticated completeness. Import protects stable domain-separated upstream member-ID, parent-ID and original-group anchors shared across different sender releases. Every selected member shares the complete family anchor set, and the declared component identity remains upstream provenance; the complete protected set must fit the existing thirty-group budget or the whole import is refused. Existing protected origin anchors propagate unchanged through further owner transfers. Fixed imported text splits remain effective after task edits or deletion; conservatively accept fixed text source splits in existing generic snapshot readers without changing v1 target/file schema. Retain -1/0/1 through actual external parsing: released ir_measures0.4.3 unchanged Qrel/read_trec_qrels definitions may be source-loaded from exact verified util.py using stdlib only, explicitly labeled as such rather than full installed-package execution. Metric/provider/package initialization is outside scope.

Second-owner import validates the complete manifest/file/asset/revision/target/family proof before atomic insertion. New local IDs and local draft review/history/unknown rights replace sender-local approval. Remap all selected document references and parent IDs; retain original records/claims as upstream provenance. Preserve original frozen source split and protected source/family anchors in an owned immutable import-binding table. Selected links to unselected upstream parents are retained as protected origin groups, not invented local IDs. Import uses a whole-bundle transaction: duplicate source text, malformed packet, bad hash, conflicting proof or publication/history failure rolls back every record and binding. Imported exact drafts require review of documents before queries; deliberately refresh query revisions after reviewing documents. The API/UI exposes original judgment evidence and local remapped refs without granting review.

Verification: v1 regression, strict three-state targets and numeric rejection, stale/deleted refs at Save/preview/freeze, unselected and formerly referenced bridges, fixed splits and group removal refusal, exact hash/schema/qrels, malformed/tampered/truncated archives, duplicate import and trigger rollback, fresh second-owner draft/review/export plus original frozen bytes. Actual Chromium editing covers all states, named fixed selections/reload, old-v1 editor isolation, stale refusal/replacement, real download and second owner. Independent source/browser/consumer review precedes exact local aggregate qualification and handoff. All labels/review clicks are authored QA, not a benchmark or semantic quality claim. No inference/training/downloaded models.
