## Existing evidence and boundaries

The [image training contract](../../../contracts/workspace-image-training.md) already retains per-epoch training loss and validation metrics, the selected epoch, class-ordered confusion counts and frozen per-example validation/test probabilities. It limits runs to 6–128 images, 2–8 classes and 1–5 epochs; authored fixtures establish execution, not generalization. Validation loss selects the checkpoint; test artifacts require durable exposure before viewing. [Audio training](../../../contracts/workspace-audio-training.md) similarly retains class probabilities and confusion counts, but its one history event means one complete fit, not an optimizer iteration. Its 6–256 recordings are not independent merely because intervals differ.

The [existing workspace UI](../../../../static/workspace-real.js) already shows accuracy, examples and macro F1, and clickable confusion counts leading to frozen prediction evidence and current Data correction. The useful extension is richer interpretation of that evidence. [Scientific fields](../../../../static/scientific-fields.js) already have a single-record orthogonal grayscale viewer; comparison needs alignment and stable scales rather than another unrelated viewer. The [Rheon evaluator](../../../../adapters/rheon/evaluate.py) retains reference/learned trajectories, evaluates four seeds, records relative field errors/divergence and checks timing comparisons; those solver seeds are distinct from repeated training seeds.

## Findings from primary sources

1. **Separate optimization history from data-size learning curves.** TensorBoard demonstrates training and validation metrics against epochs. Scikit-learn defines a learning curve as training/validation score against training-set size; that is a separate experiment requiring additional fits. These plots answer different questions. [TensorBoard scalars](https://www.tensorflow.org/tensorboard/scalars_and_keras), [scikit-learn 1.7 learning curves](https://scikit-learn.org/1.7/modules/learning_curve.html).

2. **Make class errors and denominators inspectable.** A confusion matrix has true classes on rows and predicted classes on columns. Row normalization expresses fractions within each true class. Precision, recall, F1 and support add class-level context; undefined metrics require an explicit convention. [scikit-learn 1.7 evaluation guide](https://scikit-learn.org/1.7/modules/model_evaluation.html#confusion-matrix).

3. **Accuracy does not establish probability calibration.** Guo et al. demonstrate calibration problems in their studied modern neural networks and find temperature scaling effective on many studied datasets. This does not establish an appropriate calibrator for Tuldok's tiny releases. Reliability diagrams compare binned predicted probabilities and empirical frequencies; Brier/log loss also reflect discrimination and uncertainty, so neither is a pure calibration measure. Isotonic calibration is especially prone to overfitting on small data. [Guo et al., ICML 2017](https://proceedings.mlr.press/v70/guo17a.html), [scikit-learn 1.7 calibration](https://scikit-learn.org/1.7/modules/calibration.html).

4. **Slices and comparable runs expose different failures.** TensorFlow Model Analysis supports metrics by feature slices and comparisons across model versions; aggregate results can therefore be accompanied by selected subgroup evidence. This is an established interface pattern, not evidence that arbitrary slices are statistically reliable. [TFMA guide](https://www.tensorflow.org/tfx/model_analysis/get_started).

5. **Finite training runs have uncertainty.** Agarwal et al. show that point estimates can change conclusions in few-run deep reinforcement learning, and advocate interval estimates and performance profiles. Their recommended RL aggregates are not automatically the right estimator for a small classification dataset. The transferable principle is to retain individual runs and reveal variation. [Agarwal et al., NeurIPS 2021](https://proceedings.neurips.cc/paper/2021/hash/f514cec81cb148559cf475e7426eed5e-Abstract.html).

6. **Respect dependence and holdout reuse.** Group-based validation keeps related observations together; ordinary independent-sample splits are inappropriate for correlated time series. Hyperparameter choices can leak information from repeatedly consulted test sets. Adaptive holdout research studies this problem and specialized ways to control it; simply logging access does not restore independence. [scikit-learn 1.7 cross-validation](https://scikit-learn.org/1.7/modules/cross_validation.html), [Dwork et al., NeurIPS 2015](https://proceedings.neurips.cc/paper_files/paper/2015/file/bad5f33780c42f2588878a9d07405083-Paper.pdf).

7. **Scientific fields require physical and temporal error views.** PDEBench benchmarks time-dependent PDE surrogates against reference solutions. Its first-party metric implementation includes RMSE, normalized RMSE, maximum error, conserved-variable, boundary and Fourier-space errors with a time dimension. This supports task-specific evaluation beyond one average loss; it does not supply universally valid physical tolerances or prove a particular model stable. [PDEBench paper](https://arxiv.org/abs/2210.07182), [authors' metric implementation](https://github.com/pdebench/PDEBench/blob/main/pdebench/models/metrics.py).

## Proposed order for Tuldok — engineering judgment

1. Extend the existing Runs evaluation surface with image epoch plots, selected-checkpoint marker, raw/row-normalized confusion toggle, per-class precision/recall/F1/support, probability display and confidence-sorted error inspection. Preserve the existing frozen-evidence-to-current-correction workflow. Show one-fit models as one fit; do not draw invented optimizer history. Label the image training-loss series as collected during optimization, since it is not a fresh evaluation of one fixed final model.
2. Compare runs only after matching task, frozen release/split membership, vocabulary, metric definition and preprocessing. Show seed, runtime, parameters and checkpoint choice beside metric differences. Mark changed-release comparisons explicitly; do not call the difference a controlled improvement. Add predefined validation slices using frozen metadata, with example and protected-group counts. Current mutable metadata must not silently redefine an old slice.
3. Add exploratory reliability diagrams with bin counts and explicit binary/one-vs-rest/top-label semantics. Keep raw probabilities and declared binning. Defer fitting a calibrator until a separate calibration/tuning policy exists. A handful of examples cannot support strong calibration conclusions.
4. Add repeated-training-run orchestration later, with individual seed outcomes and fixed-input comparisons. Distinguish variation from model initialization, split selection and test sampling. More seeds on the same tiny split do not increase independent data. Do not label standard deviation a confidence interval or bootstrap individual correlated frames/intervals as independent samples. A future interval implementation must declare its estimand and resampling unit, using the protected group/trajectory where appropriate.
5. Extend scientific viewing with synchronized reference/prediction/difference panes and error-versus-time/seed charts. Require compatible grid, time, field stage, centering and units. Use a shared reference/prediction scale and a separately labeled error scale; current per-slice automatic ranges can obscure differences. Treat zero-reference relative errors as undefined or use a documented denominator policy. Add boundary, conservation or spectral measures only where the domain defines their meaning.

All default interactive investigation should use validation evidence. Any test visualization, slice, export or cross-run comparison must pass the existing durable exposure path and identify prior family exposure. Once test feedback informs tuning or data corrections, a newly frozen ZIP alone does not make those same families a fresh holdout. These are extensions of existing custody, release and run owners, not grounds for a second execution or publication system.
