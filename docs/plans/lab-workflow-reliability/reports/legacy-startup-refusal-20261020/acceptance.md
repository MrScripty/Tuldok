schema3 application against its genuinely upgraded schema10 catalog. On frozen
source `8dbf9ae12bde9f88985ce2d11cb0757e38e60bed`, the complete qualifier exited0.

The supported explicit upgrade retained that Run, graph, record and artifact bytes.

their loaded paths and default schema3 constant, and called normal Dataset startup.

Imports, connection errors, unrelated storage errors or successful startup cannot
satisfy the witness. Every raw table, sequence and ordinary file matched before
and after this refusal; no current-code version parameter simulates old behavior.

schema3 backup/restore followed by explicit upgrade. Both original backups remained
unchanged. The task-owned disposable server had no catalog schemas afterward, as
independently queried. The existing qualifier drops its recorded fixture identity;
its old report does not expose that cleanup name, and no exact-name receipt is
invented here. Both current and pinned legacy worktrees were clean during execution.
