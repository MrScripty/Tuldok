## Selected composition and eight probes

| Probe | Final concrete disposition and evidence |
| --- | --- |
| Independent concerns/dimensions | Current data/review → immutable releases → model computation → Pipeline recipe composition → study intent/budget/selection → Runs attempts/custody → task-owned numerical interpretation → presentation/diagnostics have different owners/change reasons/lifecycles. [D1 owner table](architecture-design.md#state-owners-interfaces-and-composition); no mandated service/module count. |
| State/identity/value/time/policy/mechanism | Checked draft revisions differ from content identities/schema versions/migration numbers. Trial membership/replicate differs from material hash and execution attempt. Checkpoint descriptor binds actual clock/model/weight/transform; unchanged weights can recur at distinct clocks. Standalone fields have no physical timeline, and fit/update/wall clocks remain distinct. [D2 contracts](evidence-contract-design.md). |
| Caller and composition knowledge | Ordinary users/agents select meaningful data/model/goals/finite budget and encounter explicit human review/launch/disclosure gates. Composition wires adapters/default profiles/capture/view/observer once. Small immutable preparation/queries hide source capture, byte layouts, process control and field numerics while exposing failure, ordering/cost/access. No per-run logging or plot wiring. |
| Representative changes / forced owners | Correct label touches Workbench/review/release/new Pipeline material/trial; model or input/output/stage change touches versioned task/model/adapter compatibility and dependent material; new view over existing evidence touches renderer/query only; new recurring observation changes producer/version/custody/query; finite trial/cancel touches study/Access/Runs; optional adapter deletion leaves core usable. D1 change table and P1–P6 handoff specify actual propagation. |
| Stable interfaces / hidden knowledge | Exact refs, selected per-operation contracts, Run receipts and bounded structured evidence carry meaning. UI/agent does not parse arbitrary stdout/files or infer physics. Pipeline owns config, model owns computation/preprocess policy, task evaluator owns units/gauge/comparison, Runs owns process/artifacts. [D2 consumer transition](evidence-contract-design.md#discovery-and-compatibility-transition). |
| Evolution / verification / failure / replacement | Old v1 artifacts stay selected-only; new producer/verifier/query/view versions cut over together. Immutable snapshots survive draft overwrite and cold reopen without executing source. Current access is independent. Partial required evidence fails publication, optional observer failure preserves business outcome, required audit failure rolls back. Unknown process/commit keeps reservations fenced. Actual tests and unsupported runtime gates are named, not replaced by mocks. |
| Deletion result | Removing model definitions spreads shape/preprocessing/source knowledge into callers; removing studies spreads membership/budget/selection; removing evaluation queries spreads metric/array/capability rules into UI/agents. Retain those responsibilities; candidate remains study record, task declarations remain adapter-owned. Removing new registries/supervisors/view stores/universal graph removes incidental machinery; decline them. |
| Inherent complexity / cumulative machinery | Keep necessary lineage, immutable material/evidence, exact authority and finite study accounting behind existing catalog/Pipeline/Runs/access/runtime. Reuse observer responsibility; v2 requires explicit qualified projection/store cutover. No task marketplace, distributed scheduler, generic graph compiler or hosted service. Count of files is not the simplicity verdict. |

No umbrella artifact acquires authority merely by containing references. A package
closes inference dependencies but cannot grant execution, data disclosure or
scientific acceptance. An experiment can reference data/model/protocol/runtime
without owning their policies. Physical tables remain Metadata's responsibility.

## Evidence classes and material limits

- **Observed source/current contract:** existing owners, strict56-operation
  registry equality, final/selected-only weights/predictions, exact grants,
  nested submit wake risk, external mixed-artifact exposure gap and schema8.
- **Historical measured receipt:** actual captured CNN optimization/fresh restore
  and negative0/16 physics, with no current payload rehash or recurring capture
  claim. Native optional results remain their bounded original evidence.
- **Current actual disposable measurements:** real existing observer SQLite
  transactions, retention/lock/full/degraded behavior; actual NumPy encoding/
  reduction of explicitly authored fields. These do not qualify a new producer,
  native physics, deployment or whole HTTP/CLI instrumentation.
- **Authored runnable design:** local compact dark walkthrough, finite UI states,
  field/time/scale and correction paths; actual Chromium/keyboard/narrow tests
  prove proposed interaction only. JSON arithmetic cases are design probes.
- **Unavailable integration, bounded disposition:** pinned Torch/torchvision
  runtime and recurring capture are absent. New automatic profile stays unavailable
  until actual source-pinned producer capture/time/RSS/cold-inference gate passes.
  Optional pressure bridge/recurring producer/protected-test mode likewise stays
  unavailable. Numeric allocations are candidate bounds, not measured defaults.
  This leaves ownership/contracts valid and existing legacy capability unchanged.
- **Future product acceptance:** H1–H7, headless/observation procedures and P1–P6
  real-store/worker/package/runtime/migration checks are unrun. The completed
  design does not imply those implementation claims are satisfied.

## Outstanding choices with bounded owners/triggers

| Choice | Disposition / owner / trigger |
| --- | --- |
| Actual capture defaults, Torch serialized size, trainer peak RSS/overhead | Candidate only; adapter/runtime owner qualifies P3 on actual supported CPU producer before registration. Revisit count/cadence/caps, never infer from raw tensor arithmetic. |
| Scientific input/output/stage/operator evolution | Optional adapter owner supplies explicit version/meaning, lossless bridge and actual evidence; P4 generic core only enforces declared compatibility/custody/query. No live Rheon/lab changes required by design. |
| Hard resource quotas, GPU/remote/adaptive/resume | Excluded initial promises. Runtime/Access owner must separately design/qualify capabilities and rights before support; no hidden installation or prospective grant. |
| Legacy discovery retirement | Registry/operator owner inventories supported strict installations and publishes explicit cutover; no retirement inferred from absent opt-in logs. |
| Distribution rights | Existing local/private workflow selected. Package owner retains exact selected notices/rights; unsupported public redistribution until repository/material owner supplies policy. No relicense inferred from capture. |
| Observer v2 deployment | Diagnostics/operator owner qualifies actual boundaries/allowlist/overhead/retention and selects fresh private store explicitly in P6; default off. |

These follow-ups are product implementation/deferred capabilities with concrete
owners/triggers, not competing design owners or permission to silently weaken
selected invariants. Exact future write sets and runnable/viewable checkpoints
are in [implementation-handoff.md](implementation-handoff.md).
