# Scientific A package integration proposal

This proposal accompanies the disjoint P5 profile implementation. Authored
boundary tests are not actual producer/package/consumer acceptance. The original
057c8ab source authority and c8f5def inference contract stay exact; a compiled
runtime/source variant requires another explicit author nomination before use.

## Shared owner changes

Experiment must bind an external D2 candidate's `evaluation_sha256` to its actual
retained `model-evidence.json` Blob. Built-in candidates continue binding to
`metrics.json`. The same private exact evaluation lookup is needed at initial
selection and every subsequent candidate read after the existing verified
evidence, selection-policy, Trial and reservation checks. This introduces no
host MSE calculation or evaluator fallback. Main already owns this narrow change.

Runs, Pipeline and runtime owners need no new execution path or runtime profile.
P5 calls the existing explicit field evidence contract2 before capture, obtains
each artifact through current authorized whole reads, and retains 26 explicit
Run-artifact lineage inputs (under the existing30-input package budget). The
five author training sources and the sixth recipe-definition source captured by
ModelDefinitions remain bound to the exact published material. Existing source
population/transitive guards apply to package preparation, reads, downloads,
captures, derivatives and summaries.

Package preparation keeps the existing owner-only body and returns an inert
Trial. The author adapter executes only inside the separately admitted existing
captured CPU verifier. The captured package helper calls the literal `predict`
function of the pinned source; it does not execute a package-specified function,
import an arbitrary module or launch an alternative interpreter.

## Receipt and public projection

The classifier `fresh_inference_verification_v1` receipt is unchanged. Scientific
A uses `fresh_field_inference_verification_v1`, preserving the common candidate,
package/checkpoint/weights/runtime/consumer/probes/expected-output SHA fields and
`verified:true`. Additional fields are exact adapter/contract SHAs,
`implementation:"captured_author_adapter_v1"`, frozen `reconstruction`, and
`numerical_acceptance:"not_evaluated"`. Its single output has ordinal0, field ID
raw, dtype/shape/stage/units/gauge identity, output native-file SHA, 64 finite
`values_c_order` and maximum absolute reconstruction difference. No core error or
physical-acceptance claim is introduced. Explicit validation permissions continue
to protect the whole derivative receipt.

The current package-state API already uses an opaque bounded receipt object
(64 top-level properties) and a one-MiB whole helper response bound. This receipt
fits those bounds; no schema widening is necessary. A later selected typed receipt
union can name this exact variant while preserving the historical one. UI labels
must continue separating candidate diagnostics, package completion, captured
reconstruction and independent numerical/physical acceptance.

## Required actual gate

Once the completed real producer Run, accepted diagnostic Study selection and
compatible registered runtime are available, run the existing qualifier with
`--production-catalog`, `--snapshot-descriptor`, `--source-study`,
`--source-candidate` and a new `--output`. It prepares/approves/admits two ordinary
attempts, downloads the actual package through HTTP, verifies its whole SHA and
retains the captured-consumer receipt and two-slot charge delta. Then run the
downloaded-package qualifier with `--expected-profile scalar_a` and original
checkout/provider/cache masks. Independent evaluator comparison remains a
separate actual evidence gate. No completed state or runtime availability may be
inferred from this proposal or the authored fixtures.
