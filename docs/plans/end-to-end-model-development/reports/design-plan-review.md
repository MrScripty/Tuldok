## Eight composed-design probes

All eight are present in the plan's Simplicity And Ownership Review. They are correctly framed as candidate answers for the design effort, with concrete final dispositions required in D1/D4.

1. **Independent concepts/dimensions:** distinguishes data review/freeze, model computation, experiments, execution, numerical meaning and presentation; avoids making one product imply one authority.
2. **State/identity/value/time/policy/mechanism:** separates edit ordinals, content identities, compatibility/migration versions and training/physical/wall clocks; requires D2 classification rather than collapsing versions.
3. **Caller/composition-root knowledge:** the ordinary user chooses meaningful inputs/goals/budget; one integration wires adapters. D1 must show ordering/failure obligations without per-user observation setup.
4. **Representative changes/forced owners:** five source-backed scenarios trace correction, architecture changes, checkpoint evidence, tuning and scientific evaluation/export. D1 checks unrelated invalidation.
5. **Stable interfaces/hidden knowledge:** declared evidence and semantic queries hide file layouts, stdout parsing, operators and lifecycle inference from UI/coordinator callers.
6. **Independent evolution/test/failure/replacement:** requires distinct optional/required telemetry behavior, lifecycle/access outcomes and replacement without a second data/execution owner.
7. **Necessary complexity/containment:** identifies lineage/checkpoint/probe/comparison/study complexity while reusing established custody/access/runtime owners; declines speculative frameworks.
8. **Deletion/cumulative machinery:** names concrete reasoning that would recur if model/experiment/evidence responsibilities disappeared and keeps separate registries provisional.
