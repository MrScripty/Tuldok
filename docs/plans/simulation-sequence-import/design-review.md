# Independent design review

Reviewed before implementation on 2026-10-07. Tuldok baseline: `309a87d753f97b245385f8d6db20353ab536a836`; main remains frozen at `2fc4a46f12d73a0fa467d5482f68edb83d6df6af`. Review scope is the proposed local importer, not producer merge status, scientific qualification, or a trained model.

Producer source inspected: connector-read snapshots under `/tmp/rheon-contract`, pinned by the parent to MrScripty/Rheon draft PR 20 commit `fee7b4a139574f87b259796b1ba8698a41d31ac1`: `tools/import_dense3d_sequence.py`, `tools/test_dense3d_sequence_import.py`, `src/dense3d_sequence.rs`, and `docs/implementation/dense3d-sequence.md`. The producer importer accepts only its fixed 16x8x4 scenario and nine accepted-state frames. It checks manifest completion, SHA256 and byte count before parsing frames; strict JSON/native floats; geometry, stamps, time and diagnostics; and the frozen donor/divergence/ledger/pressure associations. Its `BASE_COMMIT` is the declared public producer base, `9cd4587a54befa61bdfddc8e35014bd3c34f02fb`, not the adapter source pin. Preserve that distinction. Hash verification establishes content consistency, not source authenticity.

The producer test fixture explicitly labels itself synthetic and does not launch physics. Its source commit, source hashes, executable hash and toolchain are placeholders. A source-derived Tuldok fixture may reuse this exact constructor and accepted-state formula, but must preserve that labeling and never imply actual exporter execution or an actual toolchain observation. The existing f32 decimal test is useful because a valid f32 decimal need not equal its widened f64 value.

The parent's reviewed storage refinement is sound: store one deterministic ZIP_STORED BLOB containing the exact `run.json` and `frames.jsonl` bytes, together with separately stored metadata and frame index; do not select the BLOB when browsing metadata. Stage only bounded server-owned temporary files for the unmodified pinned validator, then publish the prepared asset, Workbench record and initial history in the Dataset-owned SQLite lock/transaction. This keeps existing image authority and rights-note ownership intact and removes filesystem publication rollback from the asset transaction.

Design disposition: cleared for implementation. The parent accepted the following required refinements and added them to `plan.md` before implementation. These are compatibility and boundedness requirements, not a request for broader scope. Implementation qualification remains outstanding.

1. Add an explicit aggregate selected-sequence byte cap before asset BLOB reads in release preview/create and saved-selection asset checking. Workbench currently permits 5,000 records per synchronous selection; a per-asset 2 MiB cap alone permits approximately 10 GiB of reads. Use stored immutable byte counts to reject over-limit operations first. A 40 MiB aggregate sequence bound matches the existing synchronous selected-text budget. Ensure list/history/index projections never contain raw frame arrays or bundle BLOBs; each index is nine bounded entries.
2. Give sequences explicit source and task branches throughout `_get`, `asset`, annotation validation, filters, editor rendering/save and canonical release output. The current `_get` treats every non-image as text and calls `original_text.encode()`; `asset` treats every non-text as an image; the UI treats every non-image as a text task; canonical release uses `.txt` for every non-image. A sequence needs a stable source revision, immutable bundle hash/source identity, `sequence_transport`, a strictly bounded review-note annotation, and a `.zip` asset filename. Update release coordinate/scope descriptions to acknowledge original staggered fields and whole trajectories.
3. Sequence import must publish `draft`, with unknown rights by default, irrespective of contract verification. Sequence release must require `human_reviewed` even though canonical export currently also allows `programmatically_verified` for other tasks. Do not grant sequence programmatic review through a trusted verifier. Sequence annotation/review saves retain existing record/source CAS, append-only history, rights correction projection and independent editor ownership rules.
4. Protect derived trajectory and constructor-family groups server-side on every sequence save, rather than relying on textarea contents. Derive the family key from validated geometry, physical configuration and native constructor fields; remove volatile carrier/liquid/boundary/inlet IDs and versions, producer commands/paths/toolchain and provenance hashes. Keep actual stamps and provenance unchanged in the asset and inspectable metadata. Existing connected-component allocation already supports such groups, parents, exact duplicate hashes and unselected bridges; do not introduce frame-level records or frame allocation.
5. Rebuild only the `workbench_records` kind CHECK constraint in one transaction. Preserve every column value, record identity/revision/history and the `workbench_content` index. Inspect and reject unsupported triggers/indexes before mutation rather than silently deleting them. Verify rollback of failed migration and idempotent reopening. No protected branch updates are needed.

Relevant existing authorities inspected: `workbench.py` schema, source joins, import/save/history/rights-note/asset/selection owners; `app.py` Dataset initialization and same-origin bounded JSON transport; `dataset_releases.py` canonical eligibility, hash checks, connected components, family snapshots/allocation and archive publication; `saved_selections.py` exact revision-pair retention/source checks; and `static/workbench.js` refresh, editor epochs, unsaved edits, selection intent and release freshness. Existing code does not require a second image database or a broad 3D editor.

Required evidence before final acceptance: producer-source pin/hash retained; exact raw two-file roundtrip; source-derived fixture label; malformed/hash/truncation/wrong-axis/invalid-stamp/nonfinite/association/native-float controls; pre-mutation byte limits; asset/record/history insertion rollback; migration preservation/rollback; sequence human-only review and immutable groups; cross-trajectory constructor-family allocation; reviewed canonical release byte roundtrip; and browser import/inspection/review/reload/narrow layout while preserving an unrelated dirty editor/selection. Full aggregate checks remain required by the parent task. No implementation was performed by this reviewer.
