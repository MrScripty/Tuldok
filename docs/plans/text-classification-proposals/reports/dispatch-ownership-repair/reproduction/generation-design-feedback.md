Accepted successor design review

Parent selected a durable dispatch generation rather than the earlier tentative dispatch mutex. The original b1 reproduction and tentative feedback are retained verbatim; this document supersedes only that implementation recommendation.

Every explicit dispatch must advance a strictly validated generation tied to the exact canonical pending frame in the same committed IndexedDB transaction before POST. An initial definite 4xx may retire only the exact request ID/body and the unchanged generation captured by that dispatch. If a sibling explicit retry already committed a newer generation, cleanup must preserve both durable pending and its mirror, local pending body, and recovery ID. The four regressions should continue to permit two overlapping identical-ID/body POSTs, while older refusal cannot authorize a changed third ID.

The existing storage lock serializes Claim and cleanup, and IndexedDB remains the authority across stale localStorage caches. Increment and refusal comparison belong inside the transaction, not in pre-read JavaScript checks. A captured generation must remain an immutable per-dispatch value rather than a later shared-state lookup. Generation commit failure means zero POST. Safe-integer overflow, malformed metadata, mismatched raw body, unexpected keys, orphan metadata, and unavailable storage need explicit fail-closed behavior. Do not infer sole dispatch from missing legacy metadata; a recovered existing pending frame is unknown prior admission, even if its first newly written counter happens to be one.

Lost acknowledgment or page termination preserves the canonical pending body and dispatch history. Reload never automatically POSTs. An explicit unchanged retry advances generation but remains a repeat; its 4xx does not establish whether an earlier unknown dispatch arrived. Timeouts and generation counters are not permission to discard uncertainty.

Per the parent's explicit decision, a matching canonical successful POST or exact GET can reconcile the whole admission ID regardless of dispatch generation. The backend checks persisted request ID and intent hash under its lock before new job admission; subsequent exact-body retries therefore replay the existing job. This is stronger evidence than a refused attempt and does not require an outstanding-dispatch ledger. Keep exact raw/ID/body CAS so older matching receipts cannot erase a successor body. A refusal-generation mismatch must return before mirror removal or retirement-marker writes.

Successor qualification should include both held and lost-ACK sibling cases, persisted crash/reload generation, malformed/missing/overflow generation, commit abort with zero POST, stale refusal CAS preserving byte-identical mirror, matching receipt reconciliation, and sole fresh refusal recovery. Bounded actual native IndexedDB and overlapping HTTP fixtures remain necessary alongside the independent VM scenario.
